# 全生命周期协调协议

本协议的专业步骤服从[阶段出口与预算](phase-control.md)：维护/局部请求保持范围；昂贵动作先核主张与成本；两次不同修复或两轮无信息增量必须复评；无可行检验就交付报告。恢复不重置预算或重复完成事项。


> 按任务查阅本参考的相关部分，灵活组合步骤；它不是逐项审批流程。具体输出以用户目标为准。


## 本步如何推进科学论证

完整研究依[四段科学论证主线](research-quality.md#四段科学论证主线)维护同一可修订的论证：真实缺口→前作局限/竞争解释→核心贡献与反驳检验→新增认识/范围。选题先定位未知与最小检验；设计分解不同预测；实际研究据输出修订；主图和稿件展示已成立证据。每个适用专业步骤继续必调来源，不新增独立审批表。阶段出口与恢复复用现有路线板的论证、证据版本和下一动作；无须重做可靠成果。足够证据进入成稿，反证改写主张，不能为维持故事无限扩展；局部任务仅处理相关环节，维护交付后结束。

## 目标与启动模式

识别用户是在从零研究、接续项目、补全稿件、修订、单项审查或回应审稿。只开展此次授权范围。已有材料优先盘点与验证；不得因为要使用本系统而重新做已经可靠完成的工作。

总控是可选协调入口，不是每个小 Skill 的前置条件。可用模块见本地 module-catalog。宿主已安装某模块时按其独立契约使用；本地模块不可用时仍须用已安装skill自带的必调工具调用14库内匹配源码流程，准确记录宿主适配；匹配来源不可用就停止该专业步骤并报障，禁止自行推理替代。单凭目录层次不保证宿主会自动发现模块。

## 研究逻辑而非固定流水线

从零研究通常依次涉及：领域与资源 → 标杆期刊及文献检索 → 摘要筛选 → 重点论文全文/图表/方法精读 → 比较与候选选题 → 创新和可行性论证 → 设计与治理 → 数据获取与准备 → 实际分析 → 稳健性与复现 → 图表与稿件 → 引用及内部审查 → 最终选刊与投稿包 → 授权投稿 → 审稿修订 → 校样及归档。

顺序可调整，但不能打破科学依赖：预设与事后分析要有真实时间边界；分析、推导或解释依赖相应数据、材料或形式命题；数据图依赖真实结果；最终稿件的核心结论依赖证据；提交依赖作者授权。

构思可以先行；正式确定新选题前，学习领域标杆的具体问题、材料、方法与相关图表，并核对最近邻工作。已有可靠精读记录直接复用；只读到摘要时将判断用于初筛，再补影响决策的正文与图表。

## 研究状态

多阶段任务需要续接时，记录实际任务与产物依赖，而不只存一个线性 current_stage。默认computational-autonomous，分别记录学科、文章类型、证据类型、执行模式、方法与后端；用最少信息说明数字完成路径、输入版本、最近邻增量、竞争预测、真实产物和下一决定性动作，原研究类型保留适用知识。

现有笔记维护三个轻量队列：研究（新思路、基线、关键验证、推导/边界与独立检查），成果（图、写作、引用、数值、渲染/选刊），外部（作者、声明、访问与提交）。每个缺口对应能执行的动作，等待外部时继续独立研究与成果；无须重复建表。使用结构化工作图时按版本合并；输入变动后重查受影响的下游，不重做无关工作。

## 阶段决策

完整原创研究采用贡献搜索 → 决定性设计 → 实际发现循环 → 贡献锁定 → 正式全文的依赖；不是只要有一批结果就切换写稿。贡献搜索、贡献升级与稿件回传按[研究质量](research-quality.md)执行。异常、失败与近邻重叠反馈为新假设、方法或设计并再检验；新证据改变核心判断就重新打开研究队列。允许探索笔记和方法草稿，不以高完成度、低增量的全文替代研究目标。

决策可以是 continue、revise、redesign、pivot、stop 或 await_external_action。缺材料主动取得免费合法字典/代表记录并匹配，人工采集主题优先公开数字记录、模型或理论；资源不足校准并改进算法/规模，已知原理作基线继续发展增量。科学性不足不能靠换期刊或润色解决；高质量零结果、复现结果和推翻原假设并不自动触发 stop。研究问题已有人研究，也不等于所有新的复制、稳健性和边界研究都无价值。

审查节点包括：选题是否可研究；方法能否支持目标主张；数据是否适用且可合法获取；研究能否实际执行；结论是否与诊断和不确定性相容；稿件是否如实报告；期刊与材料是否匹配。每个节点都保留未核验部分，不用一个“顶刊分数”掩盖缺口。

## 工作单元与整合

允许宿主自行规划顺序、并行、委派与工具。仅定义工作单元边界：目标、输入快照、输出、可接受证据、允许动作和资源限制。文献不同来源、论文精读、期刊核查等可以独立工作，但共同筛选标准、变量定义、统计口径和版本必须一致。

执行结果经证据审查与去重后整合。相互冲突的样本量、DOI、模型设置和结果不能取平均或凭票数决定。原数据和冻结输出不接受并发覆盖。不同参与者对同一证据的重复总结不计作独立证据。

## 完整论文请求的交付义务

总控的 primary_research_deliverable 必须映射到用户要求的真实主体产物：整篇论文请求对应实际稿件，不得以计划、索引或验收报告替代。用户只要求规划时，主体产物才可以是研究方案，并明确缩小范围。

用户请求论文时，先推进当前数字证据内有价值的贡献与检验；核心贡献锁定后形成真实可编辑稿、图、补充与声明，结果ID/证据定位连到关键出现位置，源/图/引用变更重建受影响导出，分核字节、数值和语义。已可完成的正式稿不能用计划、评审意见或目录替代；贡献仍未成立则继续研究，不以完整低增量稿充数。确实达到授权资源或外部访问边界时交付真实在研成果、具体障碍与下一检验，不宣称论文完成，不悄悄删除缺失主要结果以通过验收。

完成声明分别报告：任务范围完成度、结构检查、科学与方法审查、来源核验、视觉检查、作者确认和待办外部动作。不得把自动校验器退出码等同于“达到顶刊水平”，也不保证发表。
