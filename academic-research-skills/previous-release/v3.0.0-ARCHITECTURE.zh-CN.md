# 3.0.0 定稿架构

宿主负责工具、环境、资源和执行方式；19个独立能力负责研究目标与实际产物；GitHub上游负责可替换实现。证据交接与工作图只在需要复现或跨阶段协调时使用。没有中央服务、固定模型或固定队伍。

短入口 → 当前缺少的专业参考 → 选中的真实执行器。先利用现有材料；需要软件时准备相应依赖；缺一项能力只影响相关工作。探索与构思可以先行，正式结论依据数据、资料、推理或证明。

文献发现和顶刊精读支持问题、方法与图表学习；创新检索保留非顶刊最近邻。研究类型允许混合与扩展；理论、人文、定性和综述不套用同一统计流程。完整稿件仍保留30项专业写作参考，但不逐条填空或调用30个工具。

上游动态链：repo → 当前ref → commit/tree → 选中入口/支持资源 → 源码与环境 → 实际执行。新任务可发现更新，续接复用已知版本；fetch/bind/config使用同一标识。机械流程可适配；实际专业条件、数据权限和研究事实按具体任务处理。

开发时由src/common单源维护，发布时生成每个独立能力的本地副本。scripts/build_release.py --check检查生成漂移；运行时不依赖src或相邻能力。日常版保留专业参考和工具，源码版额外包含测试与评估。

结构化工作图是可选辅助器：没有声明上限就不默认给研究一次机会；明确预算继续生效。比较可开始任务和正在执行任务的写路径，整合者按实际资源协调。它报告冲突，不启动后台队伍。
