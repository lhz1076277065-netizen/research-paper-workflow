# v3.4.1 维护与执行架构

1个总控与18个独立专业能力保留详细协议。完整研究由总控组织主张、证据、阶段和交付；局部任务直接进入对应能力，维护任务在版本与安装核验后结束。执行者是当前Agent及其现有模型，研究模型是科研对象或算法。

公共脚本、参考和资产的维护源是 `src/common`；短入口、能力专属交接与开始说明维护在 `src/quality31/payload`。`scripts/build_release.py --write` 生成发布副本，`--check` 核对漂移；能力专属 `protocol.md` 保留在各目录。根目录 `research-paper-workflow` 是保留旧工具的同步兼容副本，同名能力只安装一份。

每个完整能力目录独立携带必要脚本、参考和资产。所有专业步骤先执行[必调流程](mandatory-professional-flow.md)：`professional_flow.py begin` 从指定14库选择匹配的固定版本入口，读取并实施实际专业工作，`finish/check` 绑定当前任务、输入与产物后才移交。能力索引含23个入口及413条固定源文件绑定（去重为404份仓库/commit/路径文件）；缓存准备、读取指导、实施工作和运行函数分别记录。来源缺失或必要条件失败就停止受阻步骤，不以当前Agent的通用推理替代专业调用。

来源按实际类型区分 Skill 协议、代码工具、参考代码和工作台协议。可在已核实入口内适配当前宿主，保留专业实质与明确限制；参考书、导出函数、单次搜索或本地校验不能冒充完整专业流程。最终表达同样先调用匹配入口，再整理论证、保持证据并复核受影响事实；旧 `research31.py` 记录接口不豁免新的专业调用。

完整研究按可行性、设计与最小验证、必要正式研究、图稿与复核、交付推进。未给预算时可行性最多45分钟；已有预算直接沿用。`phase_control.py` 保存截止、实际计量基点、当前步骤、产物与下一动作，出口拒绝遗漏已开始的步骤。证据足够可以按真实设计产物和理由进入成稿；无可行的决定性检验交付研究报告。恢复、换回合或重试不重置预算。

阶段工具只检查经过它的动作、管理自己启动的进程组，不能替代宿主计量、目标状态或权限。`research31.py sources/select/upstream/assess` 与旧结构检查接口继续兼容；缺失历史信息保持未知，不重跑已结束研究。`result_links.py` 按需核对真实结果及导出身份，软件通过不认证科研新颖性、专业语义或投稿就绪。

程序发行包固定到 v3.4.1 源码提交并包含逐文件摘要。维护源码、失败记录和验收档案保留在源码包，日常运行包不携带测试答案与历史实验。GitHub 后续文档补充的提交及文件单独披露，见[发行与文件导航](RELEASE-v3.4.1.zh-CN.md)。
