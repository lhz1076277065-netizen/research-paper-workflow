# 审稿修订与逐点回复

本协议的专业步骤服从[阶段出口与预算](phase-control.md)：维护/局部请求保持范围；昂贵动作先核主张与成本；两次不同修复或两轮无信息增量必须复评；无可行检验就交付报告。恢复不重置预算或重复完成事项。


> 按任务查阅本参考的相关部分，灵活组合步骤；它不是逐项审批流程。具体输出以用户目标为准。


## 本步如何推进科学论证

依[四段科学论证主线](research-quality.md#四段科学论证主线)，把科学意见定位到缺口真实性、前作评价、决定性证据或意义范围，并优先处理会改变核心判断的要求。新增结果若削弱原解释，同步修订图、摘要、讨论与回复。交付说明真实完成的检验/改动、当前可支持的新认识及仍未解决部分；未授权的新研究给具体方案，不以承诺或更强措辞替代证据。

## 锁定轮次与基线

识别期刊、编辑决定、轮次、期限和对应稿件版本；用户已给信息不重复询问。保存原稿、意见、前次回复和原始结果，建立本轮基线。审稿资料的保密限制同样适用外部工具与 AI 使用。

## 拆解意见

将编辑和各审稿人的意见拆成可定位的独立请求，保留来源和顺序。复合问题要拆分但不遗漏原意。分类科学、方法、统计、额外实验、文献、解释、格式、声明或不同意之处。

## 应对计划

每项判断接受并修订、补解释、补真实分析、部分接受或有根据不同意。给出需要的材料、实际可行工作、成本与依赖；额外人工/实体实验无法在电脑内完成时，发展合法公开资料再分析、仿真或理论的可检验替代，明确支持范围和未完成请求，不能冒称等价物理证据。编辑要求与相互矛盾意见应解释处理原则，不伪称同时满足冲突要求。

## 真正修改与新增证据

执行可行且授权的新分析/实验、重新检验与更新图表。新检验保留事后性质，结果无论是否有利都不能隐瞒。输入或结果变化后更新摘要、结论、图表、补充、声明和引用。

不能为满足某位审稿人添加无关引用或改变真实数据。不能完成请求时解释具体限制与替代方案，不声称实验已补。

## 写逐点回复

对每点说明理解、回应、做了什么、证据、准确新位置；不同意时给出可核查理由而非对抗语气。“已修改”“已增加”“已验证”等动词仅在有真实改动或执行记录时使用。页/行位置对应最终修订稿，不沿用变更前位置。

## 一致性检查

建立 comment → action → actual diff → evidence → response → location 链。检查每条意见有回应，每项声称的修改在稿件或附件实际存在，回复中的数字与新版结果一致。干净稿、标改稿、diff与回复匹配；结果/源稿变化重建受影响图、补充与PDF，核实际渲染依赖、关键数值、结局和时间；不能只给回复信却未改稿。

## 交付与再提交

交付完整修订稿、适用的标改稿/差异、逐点回复、变更摘要和未解决项。研究补证、稿件/回复成果和作者/提交外部事项分列下一动作，等待外部确认时继续独立工作。再次投稿按授权，实际回执前不标resubmitted。反馈闭环完成不表示审稿人已经接受解释。
