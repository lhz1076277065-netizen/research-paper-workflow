# 原问题、实验与论文对齐

完整研究使用本参考；局部写作只保留请求涉及的问题。每个专业步骤仍先走[14库必调流程](mandatory-professional-flow.md)。研究约定与结果索引是现有研究记录的组成部分，不另设审批或重复评审链。

## 固定什么，允许改变什么

从真实用户请求和选定方案保存研究对象、核心关系、目标范围、全部必答问题及完成标准，为问题赋予稳定ID。开放选题在选定主问题时锁定；固定问题从接入时保留。标题可优化措辞，方法可依证据调整，假设可被推翻；不能借换题名、单元名称、模型或容易取得的数据把A–B研究换成C–D研究。旁支明确标为可选，不能替代尚未回答的必答问题。

`research_commitment.py`把不可变约定文件和真实请求绑定到phase；先将title、objects、relationship、scope、completion_criteria、questions及primary_experiments保存到contract-v1.json，字段和命令详见`--help`。例如：

```bash
python3 scripts/research_commitment.py --state project/phase.json bind --root project --specification contract-v1.json --request request.md --brief research-brief.md --request-quote '来自真实用户请求的原句'
```

专业begin使用可重复的`--question-id`，区分`--work-kind primary|supporting|exploration`；默认`--purpose formal`，诊断显式`--purpose diagnostic`。不要把上面的占位引句当授权证据。

专业begin还可重复使用`--experiment-id E1 --experiment-id E2`，明确本步涉及的实验；ID须属于所选问题。同一问题有多个实验时，窄范围步骤应显式绑定，以便只使被修改方法对应的步骤失效。未声明时，实验与稿件步骤按关联问题保守绑定；完整研究设计和整稿写作覆盖全部主要实验。方法变化不要求重做输入未变的数据获取与解析，其文件、来源和数据版本仍按原规则核验。

改变固定科学目标需要真实用户指令及受影响范围，使用bind的`--science-revision --revision-reason`保留依据。语言、格式、进度、交付样式等普通指令通过phase instruction的`--kind operational|presentation`记录，只影响相关产物，不使未变数据、实验和审查全部失效。主要实验和方法属于实现计划；确需改变时以`--implementation-reason`保留旧版本、原因及对原问题的影响，无须科学目标变更或人工解锁。

科学变更后，旧单元、路线和收据留档，被替代的未消费专业步骤记为cancelled，下一动作转为复评新约定和设计。通过现有phase reassess返回所需阶段，沿用真实预算、计量与容量记录。方法变更只取消受影响的未完成步骤；已完成结果按单实验指纹核验，未变实验仍可复用。旧目标的失败路线不能证明新目标已无路可走。

恢复首先读取研究约定、全部必答问题及回答状态、关键结果和下一项必要工作，再读取当前阶段与少量产物。最近的模型、下载任务或评审意见不能覆盖原问题。摘要用于定位，关键判断回到对应真实材料；已否定的假设不因压缩恢复而重现。

一次恢复仅验证一次约定，并共用实验索引及本次文件摘要；不跨调用缓存核验结果。当前工作、候选路线和待办计数排除已被新约定或方法替代的记录。结果仍以轻量文件观察定位，写作准入及最终交付继续核验完整内容和来源。

## 执行成功不等于得到答案

每个研究单元、专业步骤和核心结果关联相应问题ID。checkpoint分别说明实际检验是否执行成功、结果能否回答原问题、证据和下一动作；旧outcome继续保留，旧inconclusive或缺字段保持未知，不能迁成可靠零结果。

checkpoint使用`--question-id`、`--experiment-id`、`--execution`、`--answer`、`--validity`及真实`--result`分别保存这些判断，不能只填outcome；`--kind primary|exploration`区分必需研究与旁支。写作前绑定实际执行版计划与全部主要实验结果索引：

```bash
python3 scripts/research_commitment.py --state project/phase.json results --root project --research-plan research-plan-v1.md --result-index results/index-v1.json
```

最终用同一脚本的`delivery`附`--root`、`--research-plan`、`--result-index`、`--manuscript`、`--coverage`、`--review-started`、`--review-finished`及实际润色收据`--expression-started/--expression-finished`关联交付。文件绑定检查不等于语义审查。

| 实际情况 | 可写出的判断与后续动作 |
|---|---|
| 有效检验支持、否定或修正原假设 | 按真实方向、效应、不确定性与范围回答原问题；反向结果可以完成论文 |
| 检验对原问题有足够信息，得到可靠零结果 | 说明检验范围及精度依据，可正常成稿；不得追逐阳性或把“不显著”等同“绝无关系” |
| 尚未检验、运行失败、数据或设计不足以回答 | 保留未回答状态，诊断并实际实施适配原问题的修复；不能写成“没有关系”或论文完整完成 |

成稿前沿“问题→实际检验→结果→正文位置”核对全部必答问题及主要实验，遗漏返回具体修复动作并自主继续。程序能核对ID、版本、文件与覆盖，不能认证科学含义；问题是否被有效回答必须在来源指导下实际阅读设计和结果。

## 研究条件服务问题

必要门槛来自原问题、设计和主张。模型假设不适用时比较稳健替代、变换、适配设计或其他能回答同一问题的方法，说明代价并实际验证。不要把某种模型的全部理想条件变成所有研究的统一准入，也不能靠删掉目标或夸大解释绕过真实科学限制。

创新高度、阳性方向、最高性能、非必要外部验证和额外模型不自动成为完成标准。原问题已得到有效回答就进入成稿；额外贡献可列可选。补证同时考虑支持、推翻与不能区分的结果，不反复找材料证明预设观点。原问题仍未回答时继续自主解阻，真实预算、暂停、权限及累计下载/项目占用各200 GB边界保持。

## 诊断与正式证据分开

专业步骤默认purpose=formal。purpose=diagnostic可在全部数据未齐时使用已经核验的部分数据，检查解析、模型假设、代码和资源成本；同样必调来源，保存实际输入、结果及限制。诊断不能替代正式数据齐备检查、正式实验收据或论文核心结果。正式实验仍按[本地数据流程](local-data-workflow.md)完成全部必要数据落地及准备；合理零结果不等于实验失败。

## 把研究写成整篇论证

写作实际消费研究约定、执行版计划、全部主要实验的结果索引、真实结果与图表。先连出“原问题为何值得问→为何采用该设计→各主要实验如何回答→答案及范围”，再组织全文，而不是按Agent调用、日志时间或文件产生顺序拼接章节。四段主线是论证功能，不是强制段式。

每项主要实验在正文交代目的、关键方法、实际结果及其对问题的意义；完整参数、附加诊断和次要结果可入补充材料并在正文定位。不能只把实验留在日志、结果表或附件，也不能以一段总体总结替代不同必答问题的答案。未经开展的实验不写入完成时态。

预算、安装、Skill收据、修复历史、签收状态放在独立交付记录。正文保留理解和复现科学结论所需的数据来源、样本、处理、设计、方法、失败影响、必要限制及适用AI披露；清理内部流程不等于删掉科学方法。

## 在既有专业审稿中修复语义

一次manuscript-review同时核对原目标与结论、主要实验覆盖、设计—结果—解释衔接、段落叙事和内部流程污染，指出真实稿件位置、证据与实际修订。既有引用审查继续按能力执行，但不为这些视角另开重复全稿审批。

润色另存稿件并对照实际差异检查含义与事实。例如数字未变，而“尚未检验关系”变成“没有关系”，仍是实质错误。核比较对象、时间、范围、方向、因果强度、零结果与未检验的区别，以及主要实验是否被删漏。修复必须落到正文；状态字段、词频或“已审查”声明不能替代阅读。未变部分复用已有审查，只复核实际受影响内容。
