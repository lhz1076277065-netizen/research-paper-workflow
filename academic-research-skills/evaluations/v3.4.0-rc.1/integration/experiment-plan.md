# 软件集成验收方案

本文件按 sleep-experiment-plan 的 claim→evidence→run order 流程制定。它服务 Skill 软件验证，不是科研课题，不产生原创论文。

主张C1：阶段已经截止时，经控制工具启动的命令不会被执行。反主张：状态只写了停止，但实际仍启动进程。证据必须是真实文件标记和子进程退出记录。

主张C2：专业入口可以在固定源码身份下处理实际本地测试产物。反主张：只有来源清单或成功标签，没有实际产物。

核心块：①6个已过期与6个仍活动的状态，各比较直接启动与受控启动，命令都只写本地标记；②计量/重复启动/恢复的自动化场景；③实际来源CLI或指导处理这些文件。前两块进入验收正文；不做科研模型大规模训练，不发论文、不追求统计显著性。

观察单位是同一台Mac上的软件调用，trial配对。主指标：过期状态实际启动数；活动状态实际启动数。完整保留负结果。固定设计，无随机种子，不把24行视为24个独立科研样本。阶段同机器、同命令，无调参选优。

顺序：状态/文件真实性→进程接受与拒绝→EDA→数值/证据审查→图与表达→交付。失败就定位控制或适配问题，不新增课题。测试预算最多5分钟；网络检索另限60秒、最多3个来源记录，仅验证连接与筛选，不等同文献综述。
