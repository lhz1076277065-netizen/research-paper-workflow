## 1. direction-no-data：罕见天气下共享单车预测可靠性

已从 [UCI 官方 Bike Sharing](https://archive.ics.uci.edu/dataset/275/bike%2Bsharing%2Bdataset) 下载原始 ZIP、小时/日数据及 Readme 字典。数据持久标识为 [10.24432/C5W894](https://doi.org/10.24432/C5W894)，创建者 Hadi Fanaee-T；官方页面标明 CC BY 4.0，可免费研究使用，须署名。原始 Readme 还要求引用 Fanaee-T 与 Gama 的数据相关论文（doi:10.1007/s13748-013-0040-3）。下载日期 2026-10-01，URL、状态、字节数与 SHA-256 在 `download_log.json`。

实际成果：`direction-no-data/raw/bike.zip`、`raw/hour.csv`、`raw/day.csv`、`raw/Readme.txt`、来源 HTML、`sample.csv`、`suitability.json`。样例包括最初 12 条、全部 3 条天气类别 4 记录及 8 条类别 3 记录，选取方式明确，只用于展示字段和可行性。完整小时文件用于覆盖检查，没有用这个有意选择的样例估计天气比例。

| 必要信息 | 实际字段/检查 | 能支持什么 |
|---|---|---|
| 时间 | dteday + hr，2011-01-01 至 2012-12-31，17,379 个唯一小时 | 允许按时间划分；完整 731 日网格缺 165 小时，不能自动补为零需求 |
| 天气 | weathersit、temp、atemp、hum、windspeed | 有同期天气，未提供事前天气预报；部署预测须处理信息可得时点 |
| 结局 | cnt；全量核验 cnt = casual + registered | 系统实际租借量；供给不足时不是潜在未受约束需求 |
| 独立单位 | 单个城市系统的小时序列，731 日期 | 小时相关，按日/天气事件阻断；多个日期仍非天然独立事件；无站点或个人 ID，不能做站点级/跨城市验证 |
| 罕见天气 | 类别 1/2/3/4 分别 11,413/4,544/1,419/3 小时；类别 4 仅 3 日期 | 最极端类别证据极弱；类别 3 可做先导事件评估，但不是对真正极端类别的替代证明 |

字典有实际冲突：下载 Readme 与当前网页的 season 标签及温度归一化公式不完全一致。当前可行性路线保留原始编码，暂不据其中一种公式反推摄氏度；需核对上游处理代码/原作者说明，或后续改接有原始单位的气象源。网页实例数 17,389 与文件实际 17,379 也不同，报告采用可复算文件计数。

具体候选路线：研究“按天气事件留出、面对稀有天气支持不足时，需求预测区间何时失去覆盖，怎样用可解释的支持度触发保守区间或弃权”。比较季节/小时基线、常规强预测模型加统一残差区间、天气分层区间及支持度弃权，在同一信息和计算预算下评价 MAE、90% 区间覆盖/宽度、最差天气组覆盖及弃权后的有效服务率。用时间顺序训练/校准/验证，事件内不跨分区；随机小时分割不适合部署问题。时间相关和分布漂移下，普通可交换性保形保证不能直接搬用。

增量可能来自“可运行预测”到“可操作的失败边界与可靠性决策”，不是仅加入天气特征。[Rochas 等原作者研究](https://arxiv.org/abs/2412.03307) 已分析恶劣天气下图网络与上下文信息；本轮核实其摘要，未读完整验证细节，不能声称本路线首次。本文路线的最近邻差异暂定为事件独立性、罕见组区间与弃权，而非新的模型名。

下一项最有信息价值的动作：先按连续坏天气窗口构造事件清单，检查各时间分区的独立事件数与同期/预测天气信息边界，冻结按事件留出的先导评价。若某极端组仍只有数个事件，扩大年份并取得同城逐小时气象与租借记录，再做可靠性主张；在这之前不花预算调更大的网络。本轮已完成下载、字典取得、样例和可行性检验；未训练预测器，也未证明极端天气可靠性。
