# 全生命周期：可控的目标、可迭代的研究

只在完整研究中使用；从用户当前阶段进入，复用已有成果。当前Agent始终掌握控制权，专业Skill为当前阶段工作，不接管模型路由。

| 阶段 | 当前Agent实际要完成的判断/工作 | 可复用的专业能力与产物 |
|---|---|---|
| 问题与定位 | 为什么值得研究；已有工作解决到哪里；改变什么认识/实践 | 选刊标杆、文献与精读、创新核查；研究承诺与最近邻差异 |
| 研究设计 | 哪种证据能区分解释；数据/材料是否真的支持；替代路线 | 方法规划、数据发现、伦理/方案；研究方案与关键验证 |
| 实际研究 | 获取/处理材料，执行分析/推导/实验，并解释失败或反例 | 数据准备、分析执行、稳健性；实际结果与研究迭代 |
| 图表论证 | 哪些发现与关键例外必须让读者直接看见 | 指定库的绘图Skill完成选图—制作—核查；正式稿件图与源文件 |
| 稿件与复核 | 核心贡献是否清楚且有证据；完整写作与引用核对 | 专业写作与审查；实际全文、补充、来源 |
| 最终表达 | 用指定anti-defensive-writing整理已成立贡献；复核语义不变 | 原稿/修订稿、实际写作Skill记录与事实复核 |
| 选刊与交付 | 是否符合用户目标和当前期刊要求；有哪些研究缺口 | 最终选刊、交付索引、投稿材料；正式提交需真实授权 |
| 返修与发表维护 | 有真实意见/校样时处理；无此输入就待后续 | 回复审稿、版本更正与归档，不伪造未来工作已完成 |

用一份研究路线板记录：原始目标与当前核心主张；最近邻和关键缺口；当前阶段；阶段→实际文件→所用Skill/范围；下一关键行动与用户需要决定的事项。文字笔记即可，可选JSON仅用于规模化交接。项目不是19个Skill排队打卡，但关键研究工作不能因为入口没被读而消失。

在三个自然决策点向用户说明：选题/方法有了实质方案时，决定性结果改变原想法时，完整图稿将要交付时。用户已授权自主推进则简短更新并继续；主问题、目标层级、未经同意的外发或额外费用改变需确认。不要每个函数都请求许可。

研究完成分开回答：科学问题解决到哪一步，专业实施和图稿是否完成，投稿准备是否完成。工程测试单列，不让另一宿主端点或旧版对照包缺失成为当前论文的依赖。预算不足保存高价值进展和下一关键试验，不用一个琐碎小题冒充目标已实现。


## 续接只保存会改变决策的信息

沿用现有路线板与产物清单：原始目标/当前问题；主张、关键假设与竞争解释；最重要证据缺口；所选专业实现；已完成产物及必要版本；下一项最有信息价值的工作。中断后先读这份状态，核对实际文件与变化，再恢复受影响工作。摘要只作定位，不冒充原文。关键数据/方法改变更新真正相关结果，局部图注/排版变化不从头重跑分析。
