# 可选总控的能力编排

先识别当前用户任务，再选能力；不要先加载所有仓库。单项请求直接进入该能力的独立契约。完整研究项目也只走科学上适用的阶段。

第一批：检索→精读→创新核查→方法与数据→实际分析→图表→稿件。期刊画像/最终匹配和证据链由本项目保留，不用风格模板替代。优先专业现成实现；自己写代码只补真实接口/覆盖缺口。

第二批：仅有方案、预算、评价和停止条件时接实验循环；高级审查按威胁选择，不能固定审稿代理队伍或用分数循环修到好看。

第三批：用户需要演示、传播或完整工作台时才接 PPT/HTML/海报/视频/PaperSpine；不阻塞主线。

原材料、方法选择、主要指标、数据冻结和学术主张只有一份权威状态。外部产物保存在独立工作目录，通过输入版本与证据 ID 接回，不让另一个外部总控重建整篇论文状态。

示例：只有期刊匹配→journal-intelligence；只有一篇全文精读→paper-deep-reading；已有结果写稿→核对结果后 manuscript-writing；需试验优化→先判断计划/预算再选第二批。不为了凑模块数重新爬文献或训练模型。
