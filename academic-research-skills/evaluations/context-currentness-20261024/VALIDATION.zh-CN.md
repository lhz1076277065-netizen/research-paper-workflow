# 研究变更后的失效与续接：本地修复与验证

日期：2026-10-24。基线提交：`8d191f0`（v3.5.5）。工作分支：`codex/fix-research-context`。交付为本地源码、生成的独立 Skill、回归测试及本报告；VERSION 仍为 3.5.5，未发布、推送或更新本机安装，未续跑原研究课题。

## 实际修复

- 统一专业步骤准备、进程启动、finish/persist、审查复用、阶段出口和交付的当前性判断。历史 check 继续验证来源与文件身份，当前准入另外核对科学约定、适用实验版本、表达版本及取消状态。
- `professional_flow.py begin` 新增可重复的 `--experiment-id`；Python API 对应可选 `experiment_ids`。范围必须属于所选问题，完整设计与整稿写作保留全部主要实验。旧实验步骤按关联问题保守检查，已完成的未变结果继续按单实验指纹核验。
- 语言要求变化使旧稿和旧文本审查失效，普通进度询问保留成果。新稿和新审查完成后可继续交付；未变化的数据准备可复用。数据本身仍受原有文件、来源和数据版本检查约束。
- 科学约定变更保留旧单元、路线和收据，取消被替代的未消费专业步骤，清除过期当前工作指针并更新真实指令和下一动作。恢复与路线关闭只使用当前科学身份；原预算、计量及累计下载/占用记录保留，暂停及终态仍不可由绑定操作恢复。
- 每次恢复只验证一次约定，文件摘要在本次调用内去重，共用一次实验索引；不跨调用缓存结果。写作准入与交付继续进行完整内容和来源核验。

维护改动集中于 `src/common/scripts` 的五个脚本和 `src/common/references` 的三个既有参考，再通过原生成器同步 19 个 Skill。没有新增评审阶段或改变 14 库调用要求与资源边界。

## 开发中修正与验证范围

一次扩展检查中，过宽的数据版本限制使既有 `test_revision_preserves_quota_and_requires_current_preparation` 失败。已将共享当前性判断限定于本轮科学身份、方法和表达变化，保留原数据版本准入及旧数据步骤的审计用途；最终全库结果包含该测试通过。

最后差异审查另补了交付出口检查：旧文本全部失效后，未变化的科研辅助步骤不能单独作为当前稿件交付依据。对应正反向测试同时验证失效后的拒绝和真实新审查后的续接。

本轮使用隔离文件、固定测试来源和实际 CLI/子进程检查，验证流程、身份、文件及恢复行为。没有开展新的科学实验或第三方模型评估；历史研究与已发布验收记录保留原状。
