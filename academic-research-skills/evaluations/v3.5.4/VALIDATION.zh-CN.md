# v3.5.4 实际验收与修复报告

验收日期：2026-10-13 至 2026-10-14（Asia/Shanghai）。本版在 v3.5.3 上落实用户确认的顺序：研究计划 → 必要数据需求 → 联网选择权威来源 → 全部必要数据本地核验 → 准备与试跑 → 本机正式实验及复算 → 科研绘图 → 论文与科学审查 → 润色、事实核对和交付。官方子集满足执行计划时不下载整个数据池。

## 实施结果

- 完整实证研究默认采用六阶段 `local-data` 流程。新增数据阶段，不能借跳转理由绕过必要数据、实验和图稿；局部写作和历史记录保持其原有范围。
- `local_data.py` 将真实设计产物、版本化必要数据清单、实际来源选择收据和本地文件绑定。逐项核验文件、内容摘要、可读取性、变量与覆盖；外部格式须有实际读取程序及对应专业输出。网址和状态字段不能代替本地数据。
- 实验必须消费当前准备产物，图表必须消费实际结果，写作必须消费结果和图表，润色必须消费稿件与审查。数据或结果版本改变后，受影响的旧收据不能直接通行。摘要分块读取，大文本不整体灌入上下文。
- 缺文件、损坏或前序产物不匹配时给出修复动作，保持研究可继续。保留自主解阻、自定计划可复评、真实预算和暂停、200 GB 累计下载及项目占用分别核算。修订清单和恢复不会清零容量。
- 14 库必调规则继续约束每个专业步骤选择匹配来源；每次记录真实输入、读源、实施和输出。19 个独立 Skill 从维护源码同步生成，入口最长 798 字符，详细流程按需加载。

## 真实遇到的问题与修复

1. 设计来源 `sleep-experiment-plan` 的固定索引漏掉 3 份共享参考。补齐同一上游提交中的语言、产物清单及版本规则并校验 Git blob；保留旧证据，重新实际执行设计和数据绑定，复用未变原始数据而不重复下载。
2. 初版数据清单绑定与 `data-discovery begin` 形成顺序循环。改为先开始专业数据需求评估、再由本次步骤建立清单，记录真实 planning step；正向行为和数据版本变化测试同时通过。
3. 下载尚在进行时提前解包被并发锁拦截。验收 Agent 等待自己已经启动的下载结束后继续，没有重复下载或等待用户。
4. `reassess --blocker` 引用了尚未登记的修复。Agent 根据真实报错登记并继续；文档补明首次诊断可以省略该可选参数，不需要虚造修复记录。
5. 图表和引用收据中不充分的源文片段未通过校验，Agent 用实际适用的指导补全记录后继续；未伪造专业动作或重画未变图表。
6. 稿件审查发现计时范围与图注指标名称表述问题，润色修正且保留全部实际结果。Word 初次渲染发现装饰边框和字体颜色，修复后重新检查所有受影响页面。

自定 45 分钟计划需要调整时，Agent 已以实际审查证据自主复评后继续，原始预算基点和任务身份不变，没有等待人工解锁。详细失败与恢复过程保留在项目的 `validation-log.md` 和 `validation-continuation.md`。这是可修复障碍后的实际继续行为，不是删掉真实性、权限或容量边界。
